# Правила работы над bt-dispatch-bot

## PROJECT_STATE.md нужно поддерживать

`PROJECT_STATE.md` в корне — единственное описание системы для человека, у
которого нет ни кода, ни доступа к серверу. Устаревший файл хуже отсутствующего:
по нему принимают решения.

**Обновляй его в том же коммите, что и само изменение**, если изменение заметное:

- появилась новая функция или исчезла старая;
- изменилась схема базы — новая таблица, колонка, индекс, миграция;
- изменился стык с CRM — адрес, поле формы, селектор, порядок запросов;
- изменились тексты сообщений или кнопок, которые видит человек;
- изменился состав или смысл переменных `.env`;
- изменились роли, расписание или таймеры.

Мелкие правки — переименование внутренней функции, рефакторинг без смены
поведения, правка комментария — в документ не попадают.

**В конце файла есть раздел «Журнал». Дописывай в него строку, а не переписывай:**
дата, коммит, что изменилось с прошлой сборки. По журналу видно, как система
пришла к текущему виду.

## Секреты в PROJECT_STATE.md

Документ читает человек со стороны. В него **не попадает ничего** из этого, ни в
каком виде:

- логины, пароли, токены, ключи API, строки подключения к базе;
- значения из `.env` — только имена переменных и описание смысла;
- id чатов Telegram, @username людей, номера телефонов;
- имена, адреса и телефоны клиентов из CRM;
- SSH-ключи, пароли и адрес сервера.

Вместо значения — `<REDACTED>` или описание типа «id чата директора».

Исключение — безопасные числовые настройки: таймауты, интервалы, окна работы,
`city_id`. Их указывай как есть.

Сомневаешься, секрет это или нет — считай, что секрет.

Отдельно: в репозитории есть места с настоящими данными — справочник мастеров в
миграции 002, боевые id чатов в тестах, живой адрес клиента в `demo.py`. Ничего
оттуда в документ переносить нельзя.
